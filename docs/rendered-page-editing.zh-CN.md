# 渲染页就地编辑方案

本方案规定“渲染出来的页面本身就是编辑面”的目标契约：页面是前端，文档源是后端，打开即可打字，不需要先进入编辑状态。方案给出架构、机制边界、可行性判断、已知难点和交付顺序。

**状态：目标方案，等用户批准。** 批准前不代表已实现；已实现的接口以各包根入口 Commentary 为准。当前实现与目标的差距见[第 8 节](#8-已实现与缺口)。

## 1 需求

用一句话压死：渲染页是前端，源文档是后端，用户打开页面就能改字。

拆成可验收的七条：

1. **打开即编辑**。没有编辑模式、没有 `e`，页面出现就能打字。
2. **前端先响应**。按键先改变用户看见的那一页，后端（文档源）随后被写入同样的增量。
3. **增量更新**。一次按键只让受影响的块重排重画，不重画整页；否则版面会跳、光标会飘。
4. **不改布局地改文字**。页面不是可写 buffer，往画好的格子里塞字符会立刻破坏排版，所以编辑必须走“块内源文本 + 重排”这条路。
5. **正常编辑操作全部可用**。插入、删除、`RET`、`TAB`、`C-k`/`C-y`、选区和 `M-w`、撤销与重做、`C-x C-s`、输入法、`C-g` 都要和原生 buffer 一致。
6. **位置不漂**。光标、选区、视口在任何一次编辑之后都落在用户预期的位置。
7. **嵌入桌面和浮动面板时也一样**。窗口怎么摆是宿主的事，编辑能力不能因此消失。

## 2 结论

可行，但有三个前提，缺一个就退化成假页面。

| 前提 | 说明 |
| --- | --- |
| 编辑语义借用源 buffer，不另写编辑器 | 页面只负责位置、绘制、重排；命令在源 buffer 里执行。撤销、kill ring、输入法、`isearch` 因此原生可用 |
| 位置只认源偏移 | 画出来的格子只是显示。源偏移是唯一权威，页面里的 point 只是它的投影 |
| 重画按块作用域 | 整页重画做不到每键 16 ms 的手感，也不能让下半页跟着跳 |

已实测的三条数据支撑这三个前提（2026-11-03，703 行、16.6 KB 的真实文档，独立 GUI 实例）：

| 指标 | 实测 |
| --- | --- |
| 一次转发按键的命令耗时 | 最慢 3 ms（重画已推迟到下一帧） |
| 整页发布 + flush | 一次最大停顿 78 ms（50 ms 心跳测得） |
| 页面打字结果 | 与原生 buffer 逐字一致（`ax1 bXc`、`npnext` 两组对照） |

结论：整页重画是 78 ms 级别，必须换成块级；转发命令本身是 3 ms 级别，可以留在命令路径里。

## 3 架构

### 3.1 三层职责

| 层 | 负责 | 不负责 |
| --- | --- | --- |
| 编辑面（页面 buffer） | 光标绘制、选区绘制、指针、视口、把按键交给会话 | 不保存文字，不解释命令语义 |
| 文档会话（`etaf-document`） | 源偏移与画格的双向映射、键转发、块级脏标记、增量重画范围、存盘时机 | 不解析 Markdown，不决定块的样式 |
| 渲染器（应用） | 把源文本解析成块，把块画成 Host，按块重新发布 | 不判断字符属于谁，不处理按键 |

唯一真源是文档源 buffer 的文本。页面里不存在第二份正文；所谓“前端先改”，指先用本块的新文本把这一块画出来（乐观绘制），再把同一增量写进源 buffer，最后用源里的文本核对一次。

### 3.2 一次按键的完整顺序（打字）

```
按键到达页面
  ├─ 1 定位：页面 point → 源偏移（投影，只用所在块）
  ├─ 2 乐观绘制：把字符插进本块的本地源切片 → 重排本块 → 发布这一块的补丁
  ├─ 3 执行：在源 buffer 的该偏移上运行同一个命令（self-insert 或模式施加的变换）
  ├─ 4 核对：重读本块切片，与第 2 步的本地切片比较
  │     ├─ 相同：结束，不再重画（省一次重画）
  │     └─ 不同：按源里的文本再画一次本块（例如自动配对插入了两个字符）
  ├─ 5 收尾：更新光标所在画格，脏标记置位，安排空闲存盘
  └─ 失败：第 3 步报错 → 丢弃本地切片 → 按源文本重画本块 → 报错给用户
```

第 2 步是“前端先响应”的唯一含义：用户按下键时，先变的是屏幕。它不是第二个权威副本，生命周期只有一条命令。

### 3.3 一次按键的完整顺序（其他命令）

移动、删除、切行、粘贴、撤销这类命令的后果在运行前不可知，所以顺序是：先执行、再按脏块重画。第 2 步的乐观绘制只用于纯插入字符，这条边界必须写进契约，不能假装所有命令都能预判。

结构键（`RET`、`TAB`、删除块边界）会把一次编辑扩散成“重解析若干块 + 重建这些块的 Host”，重画范围从一块变成一组，见第 6 节。

## 4 关键机制

### 4.1 位置

| 概念 | 定义 |
| --- | --- |
| 源偏移 | 文档源里的字符位置，唯一权威。光标、选区、命令参数都用它 |
| 画格 | 页面上一个字符宽的位置，由渲染产生，可能对应零个或多个源字符 |
| 折叠 | 标记（`#`、`*`、`>`、列表符号、表格边框）在页面上不占格，但仍占源偏移 |
| 落在折叠里的光标 | 允许。画格取最近的可见位置，下一次按键仍然从记录下来的源偏移出发 |

### 4.2 增量重画

一次按键的脏块集合：光标所在块，加上源区间发生变化的块（合并块、拆块时是两块）。重画走保留式更新，只发布这个块（或这组块）的子树，策略应为 `span-patch` 或 `owner-scoped`，不接受整页发布。

排版不变量：

1. 块高变化后，其后所有行随之下移或上移，这是重排的唯一副作用。
2. 视口以光标为锚：能保持光标所在屏幕行不变就保持，否则保证光标不离开可视区。
3. 页面底部与右缘的空白不允许因为重排出现新的溢出。

### 4.3 光标与选区

- 光标画在源偏移对应的画格边界上；偏移落在折叠区里时画在最近的可见边界。
- 选区以源区间表示，绘制时投影到画格；跨块选区按块绘制。
- `M-w`、`C-w`、`C-y` 一律读写**源文本**。页面里的文字带项目符号、边框和折行，复制画出来的文字会污染文档，这是硬约束。
- 双向：从别处粘进来的文本按源文本插入，落在光标源偏移上。

### 4.4 输入法

预编辑串由系统画在窗口的 point 处。页面把窗口 point 保持在光标画格上，所以中文预编辑出现在光标位置。已知风险：光标落在折叠标记处时，预编辑可能偏移一个字宽。缓解是让窗口 point 始终指向光标画格，不做别的补偿；偏移达到两个及以上字宽才算缺陷。

### 4.5 撤销

- 每次页面编辑对应源 buffer 里的一条命令，撤销步长与原生一致（连续打字合并成一步）。
- 页面上的撤销键（`C-/`、`C-_`）转发给源 buffer 的撤销命令，然后按脏块重画。
- 乐观绘制不得产生撤销记录。撤销后必须能在页面上看见回退，且光标回到撤销点。

### 4.6 存盘与外部修改

- 页面常驻编辑，不存在“退出编辑时保存”这个时机。存盘时机：空闲 2 秒保存一次，窗口关闭或 buffer 杀掉时保存一次。打字期间不弹任何提问。
- 存盘失败（只读、磁盘满、权限）保留内存内容，mode line 显示未保存，并给出可读的错误。
- 文件在磁盘上被外部修改：脏时提示二选一（保留内存 / 丢弃重载），不脏时直接重载并重画。

## 5 难点与风险

按风险从高到低。每条给出判据，判定标准是“能不能写出可观察的验收场景”。

| # | 难点 | 现象与判据 | 代价 |
| --- | --- | --- | --- |
| 1 | 装饰格没有源区间 | 列表符号、表格边框、代码块背景、分隔线都不来自源文本。光标停在那里时删除、左右移动必须有确定语义：要么跳过，要么锚到最近的源字符 | 中。投影里增加两类格：可锚定、不可锚定 |
| 2 | 折行不等于源行 | 一个视觉行是源文本的一段。在折行点插入、删除、`C-e`/`C-a` 的语义要区分“视觉行末”和“源行末” | 中。投影记录折行点，命令按原生语义执行 |
| 3 | 一格不是一个字符 | 宽字符、组合字符、行内样式切分、行内图片。删除一格有时要删两个源字符（如表情的代理对、组合符） | 中。投影以源字符为最小单位 |
| 4 | 结构键跨块 | `RET` 拆段、`TAB` 变列表、退格合并、删除围栏。块的边界变了，Host 引用会失效，撤销时还要还原 | 高。需要块身份与区域重解析 |
| 5 | 视口锚定 | 块高变化让后续行位移，光标跳动明显，滚动位置被拉回 | 中。以光标行为锚重算视口 |
| 6 | 输入法预编辑 | 预编辑串位置偏移，或提交后页面先显示旧文本再刷新 | 低到中。靠窗口 point 与乐观绘制 |
| 7 | 选区与剪贴板 | 复制到带装饰的文字，粘回去文档被污染 | 低。强制读写源文本 |
| 8 | 撤销合并 | 一次按键产生两步撤销，或撤销后页面不回退 | 中。命令名与撤销边界要和源一致 |
| 9 | 全文命令 | `isearch`、`query-replace`、`imenu`、大纲跳转在页面上没有对应位置 | 中。先做只读定位（跳到画格），替换类命令后续再做 |
| 10 | 渲染器自己的键 | 页面常驻编辑时，渲染器的 `SPC`、`DEL`、`TAB`、`RET`、`n`、`q`、滚轮都不能再当导航 | 低。编辑会话启动时关掉渲染器导航键图 |
| 11 | 应用字母键 | `n`、`p`、`t`、`r`、`q`、`[`、`]` 现在直接占裸键，常驻编辑下会和打字冲突 | 低，但需要决定。建议统一退到 `C-c` 前缀 |
| 12 | 嵌入宿主 | 桌面和浮动面板把应用画进自己的画布，一个 buffer 里多个窗口。buffer 级的按键接管和光标绘制在这里全部失效 | 高。见第 7 节 |

第 1、2、3 条是同一个问题的三个面：**画格与源字符不是一一对应**。方案的赌注就是把这件事收敛到投影层，让编辑层只见源偏移。投影层已经被今天的实现验证过（块内收窄映射、光标只读一块），所以可行性主要押在投影的正确性和测试覆盖上。

第 4 条是工作量最大的一条，也是最容易被低估的一条：它不是“再加几个键”，而是块模型要支持重解析与 Host 重建，并且撤销要能跨结构还原。

## 6 明确不做的

| 不做 | 理由 |
| --- | --- |
| 让页面 buffer 变成可写、直接往画好的格子里插字符 | 排版会被立刻破坏，正是要避免的做法 |
| 另写一个文本编辑器（自带撤销、kill ring、输入法） | 成本高一个量级，而且永远追不上原生语义 |
| 页面自己保存一份正文并与源文件对账 | 两份真源必然漂移。乐观绘制不落盘、不跨命令 |
| 为每个块弹原生输入控件（`read-string`、递归编辑） | 不是就地编辑，输入时版面消失 |
| 放弃渲染、回去编辑源文件看旁边预览 | 用户已明确否掉 |

## 7 嵌入宿主（桌面、浮动面板）

桌面和浮动面板把应用的画面**嵌进自己的画布**，一个 buffer 上摆多个窗口。那里没有“页面 buffer”，所以现在按 `e` 会报 `Not an ETAF markdown preview buffer`，完全进不了编辑。

要让那里也能就地打字，需要引擎先提供四项能力，缺一不可：

| 能力 | 内容 |
| --- | --- |
| 输入目标 | 宿主声明某个子树接受文本输入；焦点在它上面时，打印字符与编辑键先交给它，而不是走渲染器的导航键图 |
| 子树光标 | 光标画在子树里，而不是靠 buffer 的 point 和 `cursor-type` |
| 子树选区 | 选区按子树绘制，覆盖该子树的画格 |
| 局部重画 | 重画限定在子树，走保留式更新的子树作用域；块高变化只影响该子树内部与其后的兄弟 |

对应用侧的影响：`etaf-document` 现在假设“页面就是一个 buffer”，需要把页面抽象成“surface”：buffer 或子树。位置的来源、光标绘制、脏块发布都要按 surface 分派。这是第 5 节第 12 条那项高风险的真实成本。

结论：这条能力是新的，能复用现有保留式更新的子树补丁，但不能靠改应用侧绕过。它排在页面 buffer 那条之后，见第 9 节。

已经落地并有回归覆盖的部分（`make -C etaf test` 244 项、`make -C etaf-md-preview test` 58 项全绿，2026-11-03）：

| 已实现 | 位置 |
| --- | --- |
| 编辑会话：源偏移 ↔ 画格投影（可按偏移只读一块） | `etaf/lisp/etaf-document.el`、`etaf/lisp/etaf-projection.el` |
| 键转发：页面没认领的键在源 buffer 里查同名命令并执行 | `etaf-document-forward-key` |

| 打字、删除、块内光标、选区绘制、关窗保存 | `etaf-document` + 应用侧接线 |

缺口（本方案要补的）：

| 缺口 | 现状 | 目标 |
| --- | --- | --- |
| 编辑入口 | 打开即编辑的两条 buffer 入口已具备；嵌入宿主入口不具备 | 所有入口打开即编辑 |
| 应用字母键 | 裸键 `n`/`p`/`t`/`r`/`q`/`[`/`]` | 退到前缀，页面常驻编辑 |
| 渲染器导航键 | 编辑时仍会抢 `SPC`、`TAB`、`RET` 等 | 编辑时关掉 |
| 重画范围 | 按键重画一块；结构键仍可能整页或大范围发布 | 脏块集合，结构键限定在一组 |
| 存盘 | 会话结束时保存 | 空闲保存 + 关窗保存 |
| 结构编辑 | `RET`/`TAB`/退格合并未验证到验收 | 有场景、有测量 |
| 嵌入宿主 | 进不了编辑 | 引擎输入目标 + 应用 surface 抽象 |

## 9 交付顺序与验收

每一步都能单独验收，验收不过不进入下一步。

| 阶段 | 内容 | 验收门槛 |
| --- | --- | --- |
| P1 页面 buffer 常驻编辑 | 去掉 `e`；应用键退位；关掉渲染器导航键；打字、删除、`RET`、撤销、选区、复制粘贴；块级重画；空闲存盘 | GUI 场景：打开即打字、两种宽窄窗口、撤销后页面回退；每键 p95 ≤ 16 ms；整页发布次数为 0 |
| P2 结构编辑与特殊块 | 标题、列表、引用、代码围栏、表格、图片块内编辑；拆块与合并块；块身份重建 | 每个块类型一条场景；结构键的重画范围 ≤ 相邻三块；撤销跨结构正确 |
| P3 全文命令与外部修改 | `isearch`、`query-replace`（先定位后替换）、`imenu`、大纲跳转；磁盘外部修改的两种处理 | 替换后页面与源一致；外部修改不丢内容 |
| P4 嵌入宿主 | 引擎输入目标（子树按键、子树光标、子树选区、子树重画）；桌面与浮动面板接入；应用 surface 抽象 | 同一文件在页面 buffer 与桌面窗口里，打字、删除、撤销、滚动结果逐项一致 |

性能门槛用三组独立样本：打字（每键 p95 ≤ 16 ms，p99 ≤ 40 ms）、结构键（≤ 60 ms）、滚动（无重画，CPU ≤ 5%）。测量走 `scripts/performance.py` 与 GUI 场景脚本，不靠单次观感。

## 10 待决定

四项需要用户定，其余按本方案执行。

1. **应用字母键退到哪**：建议统一 `C-c` 前缀（`C-c n`、`C-c p`、`C-c t`、`C-c r`、`C-c q`），`C-c h` 保留帮助。要不要这样定。
2. **存盘时机**：建议空闲 2 秒保存 + 关窗保存，不弹提问。要不要这样定；需要更强保险时再加周期性备份文件。
3. **表格内编辑的期望**：单元格内当纯文本编辑（`Tab` 跳格、表格对齐由重排维护），还是表格内容按列对齐、输入时保持等宽。前者简单，后者要重写表格渲染。
4. **P4 现在做还是先上 P1**：建议先把页面 buffer 这条做完整并验收，再动引擎的输入目标。
