# ETAF 区域导航与键盘交互方案

本方案规定复杂文本应用的区域导航、控件操作、编辑状态和快捷键边界，是 ETAF 生态已确定的目标契约。框架提供最小且一致的导航能力，应用决定业务快捷键和区域直达键。用户可以沿方向自然移动，也可以显式选择区域；离开编辑状态必须保留已经输入的内容。

目标行为与当前实现的差距见[实现状态与交付边界](#10-实现状态与交付边界)。本方案不表示相关功能已经完成；已支持的接口以各包根入口的 Commentary 为准。生态依赖与统一输入路径见[生态架构契约](architecture.zh-CN.md)。

## 1 核心决定

| 主题 | 确定的规则 |
| --- | --- |
| 导航方式 | 方向键优先完成控件内部操作；没有内部用途或到达允许离开的真实边界时，进入相邻区域 |
| 显式跨区 | 导航态下以 `r` 进入区域选择；区域字母精确定位，方向键直接跨区 |
| 默认键位 | 默认导航方案保护 `r`、`?` 和物理方向键；应用业务绑定不能覆盖这些入口 |
| 可选方向方案 | 内置方向键和 Vim 方向映射；Vim 映射只有显式启用后才占用 `h/j/k/l` |
| 区域提示 | 区域提示字母由应用作者确定，保持稳定；提示字母不会自动成为裸键快捷方式 |
| 应用直达键 | 框架提供区域跳转接口，应用自行决定是否绑定 `l`、`s` 等直达键 |
| 编辑退出 | Escape 退出编辑态，保留草稿和控件焦点；重新编辑时恢复编辑位置与撤销历史 |
| 原生中断 | `C-g` 保留 Emacs 原生中断语义；框架和应用不把它重新绑定成关闭、取消修改或清空输入 |
| 按键帮助 | 导航态下 `?` 查看当前有效绑定，帮助从实际声明和配置生成 |
| 基础可达性 | Tab 保留为顺序遍历入口；区域跳转和空间导航提供快速路径 |

上述默认保护限定在相应交互状态和当前应用范围内，不安装影响其他 Emacs buffer 的全局接管。最终使用者可以通过框架级配置显式改键，普通应用业务绑定不能隐式覆盖导航入口。

## 2 区域与焦点模型

### 2.1 按任务建立区域树

区域是用户能够命名并希望直接进入的功能范围，例如侧栏、结果列表、详情、属性表单和输入区。区域可以嵌套，但普通布局包装节点不自动成为导航区域。

| 区域路径 | 内容 |
| --- | --- |
| 应用／侧栏 | 分类或会话列表 |
| 应用／主体／筛选 | 查询和筛选控件 |
| 应用／主体／结果 | 数据列表或表格 |
| 应用／详情／属性 | 负责人、优先级、截止日期等字段 |
| 应用／详情／历史 | 历史记录 |
| 应用／输入区 | 单行或多行编辑组件 |

大量重复记录作为列表项目定位，不为每条记录建立区域。区域树表达任务结构，焦点组表达列表、工具栏、表格等复合控件的内部操作方式；一个区域可以包含多个焦点组。

区域声明包含稳定身份、名称、父区域和默认入口，并可配置提示字母及方向邻接关系。身份限定在所属应用实例内，不能因显示名称、列表排序或布局坐标变化而改变。字段的具体 API 名称由实现时的公共入口契约确定。

### 2.2 焦点与编辑状态

逻辑焦点、业务选择、文本光标与选区分别表达不同状态。移动焦点不自动清空多选，也不自动提交业务数据。每个输入上下文只有一个真实焦点权威；区域位置记忆和跳转历史是恢复信息，不能成为另一套焦点状态。

进入区域时，依次选择上次仍有效的操作位置、声明的默认入口、适合当前状态的可操作控件。没有交互控件但需要阅读的区域可以提供程序可聚焦的内容入口，不必为每个区域容器增加 Tab 停靠点。

焦点样式必须清楚且不改变布局尺寸；区域提示和帮助也不能通过增加字号、图标高度或边框宽度改变标准行高。进入目标时执行最小必要滚动，使目标可见，同时保持未受影响区域的位置。

### 2.3 位置恢复

区域记录稳定目标身份。重排后跟随原对象；目标删除、隐藏或禁用时，按后继、前驱、有效区域入口的顺序选择适用的回退。关闭浮层后恢复有效调用入口；应用主动切换内容后，旧入口失效时采用新内容的默认入口。

主动跨区域跳转可以记录返回位置，普通方向键逐项移动不逐次填充跳转历史。返回能力通过公共命令提供，是否绑定快捷键由应用或用户决定。

## 3 交互状态与默认键位

### 3.1 状态与按键含义

| 状态 | 文字键 | 方向键 | Escape |
| --- | --- | --- | --- |
| 导航态 | 执行当前有效的应用命令；`r` 选择区域，`?` 查看帮助 | 按控件内部操作与边界规则导航 | 处理当前可关闭的临时界面；没有临时界面时不丢弃数据 |
| 编辑态 | 正常输入，包括 `r`、`?`、区域字母和数字 | 原生编辑优先，真实边界按组件契约交给区域导航 | 退出编辑态，保留文字和控件焦点 |
| 区域选择态 | 解释当前范围内声明的区域提示字母 | 直接选择对应方向的区域 | 取消选择，恢复进入选择前的状态 |
| 帮助或其他临时界面 | 按该界面的输入规则处理 | 操作当前界面 | 先关闭最内层临时界面，恢复有效入口 |

输入法候选、补全等原生临时交互先处理 Escape。一次按键不能同时关闭候选、退出编辑并关闭外层对话框。状态转换复用 Emacs 命令循环和提供方生命周期，不在应用中另建事件循环。

### 3.2 两套方向映射

| 方向语义 | 默认方向键方案 | 可选 Vim 方向方案 |
| --- | --- | --- |
| 左 | `←` | `h` |
| 下 | `↓` | `j` |
| 上 | `↑` | `k` |
| 右 | `→` | `l` |

两套映射调用同一组方向命令，使用相同的区域、边界和恢复规则。Vim 方案可以同时保留物理方向键；它只表示方向映射，不承诺完整 Vim 或 Evil 键位兼容。

默认方案不预留 `h/j/k/l`。启用 Vim 映射时，检查其与应用业务键及区域选择字母的冲突；存在歧义时要求显式重绑定一方，保留此前有效配置。不能根据最近注册顺序或短超时猜测用户意图。

键位映射与边界策略独立。用户可选择方向键或 Vim 映射，也可配置某类控件保留原生边界行为；修改键位不应改变控件的业务语义。

### 3.3 Emacs 原生中断

`C-g` 继续由 Emacs 处理。框架和应用不得为区域选择、文本编辑、对话框或帮助重新绑定它，也不得把原生 quit 改解释为提交、回滚或关闭业务对象。

命令被原生中断时，框架释放临时提示、跟踪和局部资源，保持已接受的输入及有效焦点状态；必要清理不吞掉或替换原生中断语义。显式的应用关闭和取消操作使用其公开命令及 Escape 层级。

## 4 方向导航与区域选择

### 4.1 内部操作与真实边界

控件对方向请求给出三种语义结果：

| 结果 | 含义 | 后续处理 |
| --- | --- | --- |
| 已处理 | 完成内部移动、展开、选择或其他方向操作 | 结束本次请求 |
| 允许离开 | 该方向没有内部用途，或到达允许离开的真实边界 | 查询相邻区域 |
| 当前不能离开 | 原生临时交互正在接管，或控件明确保留该方向 | 留在当前交互中 |

不能用 point 是否变化、某个移动命令是否报错来代替上述判断。展开树节点、改变选区或切换候选都可能没有移动 point，却已完成内部操作。移动失败或未知状态也不能自动视为允许离开。

普通应用控件采用内部操作优先、边界允许出区的策略。没有相邻有效区域时停留。一次输入事件最多完成一个内部动作或一次区域跳转，不能在同一次事件里到达边界后继续跨区。

| 场景 | 输入 | 目标行为 |
| --- | --- | --- |
| 竖向列表中间 | `↓` | 下一项 |
| 竖向列表最后一项 | `↓` | 若下方有有效相邻区域则进入，否则停留 |
| 竖向列表没有左右内部操作 | `→` | 进入右侧区域 |
| 树节点仍可展开或进入子节点 | `→` | 完成树的内部操作 |
| 单行输入中间 | `←` | 光标左移 |
| 单行输入最开头 | `←` | 进入左侧有效区域 |
| 多行文本中间 | `↑` | 按原生视觉行规则移动 |
| 多行文本最上面的可编辑视觉行 | `↑` | 没有内部移动可做且允许离开时，进入上方区域 |

长按产生的后续方向事件可能在到达边界后继续跨区，这是边界导航的明确行为。支持配置保守的边界策略，真实 GUI 和终端分别验证连续输入；不能以未验证的按键释放检测或很短的超时作为可靠性保证。

### 4.2 相邻区域的选择

跨区域命令以区域为目标，不在整个界面的按钮集合中任意挑选最近控件。优先采用应用声明的方向邻接关系；没有声明时，在当前区域的同级区域中按已提交几何寻找该方向的邻居，同级没有目标时再向父层寻找出口。

例如主体的左侧出口可以明确指向侧栏，侧栏的右侧出口指回主体；主体下方指向输入区。区域内部位置记忆负责让返回操作落到先前的有效控件。

几何选择必须有稳定的候选顺序与距离相同情况下的决胜规则。布局改变后使用已提交的区域边界，不保存另一份应用侧坐标。隐藏、不可进入或被模态范围排除的区域不参与选择；相邻区域不可达时不穿透到背景控件。

### 4.3 区域前缀

导航态下按 `r`，在当前有效范围内显示应用声明的固定区域字母和可用方向。有效范围为当前应用或最内层模态界面；提示展示区域名称和必要的父路径，当前区域清楚可辨。

- `r` 加区域字母：立即进入对应区域，恢复其有效入口，然后结束本次选择。
- `r` 加当前方案的方向键：跳过控件内部导航，直接按区域邻接关系跳转。
- Escape：取消区域选择，恢复原来的焦点和状态。
- `?`：说明当前区域选择中的有效键位和目标。

熟练用户可以连续输入，不需要等待提示绘制。区域提示不依赖短时连击，也不能改变布局。选择过程中目标失效时，保留或恢复原来的有效位置并说明原因，不能把同一个字母重新分配给另一个目标后执行。

区域字母可以指向嵌套区域；同一次提示范围内必须唯一。应用只为需要字母入口的区域分配字母，其他子区通过空间导航、区域列表或公开跳转入口到达。大量子区按父区域收窄列表并展示路径，不能把布局包装层或每条列表记录都变成字母目标。

### 4.4 提示字母与应用直达键

为侧栏声明提示字母 `l`，只建立 `r l` 这一入口，不自动创建裸 `l` 的绑定。应用可以另行把裸 `l` 绑定到侧栏，也可以把它保留给业务操作。

若启用 Vim 方向映射，`r l` 已表示向右区域；此时提示字母 `l` 不能再指向另一个目标。冲突由配置校验报告，应用或用户显式调整一方。框架不为了预防可选方案的冲突，在默认方案下额外封锁所有字母。

## 5 编辑退出与输入保护

### 5.1 Escape 保留输入

普通编辑状态下，Escape 结束编辑态并进入导航态，逻辑焦点仍锚定在输入控件上。已经输入的文字、光标位置、选区、滚动位置和撤销历史应保留。此时方向键交给导航系统；`r` 和应用快捷键可以正常使用。通过 `RET` 等控件公开激活方式重新编辑时，从保留的位置继续。

```text
输入到一半
  → Escape，保留草稿并退出编辑态
  → r 加区域字母，进入其他区域查看
  → 返回输入控件并激活
  → 从原位置继续编辑
```

离开编辑、保留草稿、提交和放弃修改是不同操作。切换区域不自动发送或保存到外部系统；Escape 不恢复激活时的旧值；明确的“放弃修改”操作才按业务契约恢复基准值。

框架提供可在编辑态调用的区域导航命令，应用或用户可以配置非字符入口以减少步骤，但不增加强制的默认组合键。主流程不依赖这个可选入口。

### 5.2 边界判定与原生输入

单行输入的两端是可判定的左右边界。多行输入中间一行的行首按左，仍可能移动到上一行末尾；自动换行和滚动视口的边缘也不等于文本边界。编辑组件结合原生移动、视觉行和真实文本范围给出方向处理结果，不能由应用按字符列号猜测。

输入法组合、候选选择、补全及文本选区优先遵循原生编辑规则。Escape 先交给正在进行的临时交互，不能同一次又触发退出编辑。候选字母和未确认文本不能被区域选择器当成命令。

退出再进入的行为要通过完整编辑会话验证，不能只证明文本字符串相同。后台内容更新、区域跳转和重新显示不得清空撤销历史、把光标一律放到末尾，或结束其他输入实例的会话。

GUI Escape 与终端 ESC、Meta 和功能键序列分别验证，沿用 Emacs 输入解码，不把原始 ESC 字节定义为破坏其他序列识别的全局命令。

## 6 应用绑定与冲突规则

### 6.1 简单声明

应用继续通过“按键、处理函数、说明”声明绑定。普通命令和匿名回调均可作为处理器；声明位置决定作用域，挂载和卸载决定生命周期。根级业务键作用于应用，区域级业务键作用于该区域及允许的后代。

现有 `:keys` 的 `(KEY COMMAND [LABEL])` 形式是绑定入口的基础。区域跳转、按序号选择等能力通过公共命令或命令构造入口提供，让应用不用自行处理坐标、焦点、编辑会话和恢复。新增函数签名在实现后由包根入口统一维护，不在本方案预先定义另一份 API 清单。

| 声明范围 | 应用选择的键 | 动作示例 |
| --- | --- | --- |
| 应用 | `g` | 刷新当前数据 |
| 应用 | `l` | 进入侧栏区域 |
| 应用 | `e` | 进入输入区 |
| 侧栏 | `1` 到 `9` | 激活对应编号的项目 |

这些业务键均为应用示例，不是框架默认绑定。框架不要求应用使用单字母，不自动占用数字，也不要求普通绑定先注册另一套业务对象。

### 6.2 冲突处理

| 情况 | 规则 |
| --- | --- |
| 业务绑定覆盖当前方案的框架保留入口 | 报告冲突，指出按键、作用域和来源 |
| 同一作用域重复绑定同一个键 | 报告冲突，不采用最后注册者获胜 |
| 子区域与父区域使用同一个普通业务键 | 就近区域生效；帮助显示实际来源 |
| 互不重叠的区域使用同一个业务键 | 允许 |
| 同一个键同时作为完整命令和多键前缀 | 报告结构冲突，要求改为无歧义的声明 |
| 更换方向方案后产生冲突 | 拒绝有歧义的配置更新，保留此前有效绑定 |
| 显式修改框架键位配置 | 统一更新导航入口、校验和帮助；不能通过普通业务绑定暗中覆盖 |

编辑态的正常文字输入不属于保留键冲突。模态范围外的业务绑定不参与当前解析。一次输入只执行一个确定的处理器，禁用子控件不能把同一输入意外交给父业务动作。

静态检查覆盖框架管理的声明；运行时按键解释还需反映 Emacs major mode、minor mode、用户映射和当前交互状态。不能宣称静态校验已经排除所有用户配置冲突。

### 6.3 项目序号

`l3` 可以由两个立即执行的命令组成：应用绑定的 `l` 进入侧栏，随后侧栏的 `3` 激活第 3 项。没有配置裸 `l` 时，可用 `r l 3`。区域跳转只移动焦点，序号操作才按列表声明执行选择或打开。

编号从 1 开始，对应明确的显示顺序。滚动不重新编号；筛选、排序及分页采用组件声明并显示的编号范围。禁用项不能造成无提示的编号位移，越界序号不得改为激活其他项目。

单数字立即执行与任意多位数输入不能共用有歧义的解析。应用需要第 30 项等入口时，显式启用完整序号输入，例如应用定义的 `#30 RET`；该示例不建立新的框架默认键。不得依靠短超时区分 `3` 和 `30`。

执行时将序号解析为稳定项目身份。多位数输入期间列表顺序变化时，重新确认可见编号或取消此次选择；异步完成后不能按新的第 N 项执行旧请求。虚拟化或尚未加载的项目通过提供方支持的数据与显示接口定位。

## 7 按键帮助与可发现性

导航态下 `?` 展示当前有效的框架、应用和区域绑定，说明当前区域、交互状态、动作名称及绑定来源。临时不可用的动作提供原因；区域选择态中的帮助解释该状态的区域字母和方向语义。

帮助、区域提示和按键解释读取同一份有效绑定数据。应用只维护一份声明，用户重绑定后显示同步更新；被遮蔽的父绑定不伪装成当前可执行入口。

帮助默认用于查看和搜索，查看条目不能触发业务动作。执行型命令面板作为独立能力保留；若帮助提供执行入口，操作必须明确。图标控件和区域提供可读名称，实际读屏适配与键盘可见焦点分别验证。

编辑态的 `?` 是普通字符。帮助及导航功能提供可从 `M-x` 调用的公共命令，应用或用户可自行添加非字符快捷方式，不因此扩大默认保留键集合。

## 8 作用域与生命周期

区域跳转、帮助和快捷键使用同一份已提交的目标与可见性事实。失败的显示更新不能让旧画面使用新目标；目标失效时报告并回退，后台更新不抢夺当前焦点。

模态界面形成区域导航边界。方向、区域字母、数字选择和应用直达命令均不能绕过这个边界进入背景。只读内容与禁用操作分别处理：需要阅读或复制的内容可以提供入口，禁用动作不能执行。

绑定及提示随所属区域挂载、更新和释放，卸载或窗口失效后不保留旧回调。区域选择被原生中断时只清理临时资源，保留已接受数据并让 Emacs 中断正常传播。

高频方向输入复用已提交的身份与区域索引，不默认每次重新扫描、排序所有控件。性能记录覆盖命令处理、必要更新及实际显示提交；具体测量方法与证据边界沿用[工作区工具手册](manual.md)和[生态性能契约](architecture.zh-CN.md#113-性能门槛与证据边界)。

## 9 分层职责

| 层次 | 拥有的职责 |
| --- | --- |
| Ebox | 已提交节点身份、几何与可见性、真实焦点、滚动、原生输入边界，以及通用方向和编辑会话原语 |
| ETAF | 区域和导航命令的公共入口、作用域绑定、键位方案、事件上下文与生命周期；使用 Ebox 的事实，不维护第二份目标或焦点权威 |
| ETAF UI | 控件内部方向语义、编辑与导航状态转换、区域提示和按键帮助等可复用界面 |
| 应用 | 语义区域划分、固定提示字母、业务命令、可选直达键和数字速选、业务选择、草稿及提交策略 |
| 最终使用者 | 选择方向方案，显式改键，按需要配置边界策略和可选快捷入口 |

应用及目录组件只使用 ETAF 和 ETAF UI 公共接口。缺少的共享能力在提供方补齐，不能由每个应用复制焦点扫描、按键分发或编辑会话管理。Tab、控件激活及 Emacs 原生行为继续沿各自契约工作，不把更多按键无条件加入应用级禁止绑定名单。

## 10 实现状态与交付边界

当前公开契约已有可复用基础，但与本方案仍有以下差距。具体可调用签名以 [ETAF 入口](https://forgejo.vhkd.top/emacs-taf/etaf/src/branch/main/etaf.el)、[ETAF UI 入口](https://forgejo.vhkd.top/emacs-taf/etaf-ui/src/branch/main/etaf-ui.el)和 [Ebox 入口](https://forgejo.vhkd.top/emacs-taf/ebox/src/branch/main/ebox.el)为准。

| 能力 | 当前公开契约 | 目标差距 |
| --- | --- | --- |
| 焦点与方向 | Ebox 已提供共享焦点、焦点组、方向导航、模态范围与滚动显示；ETAF 提供对应入口 | 增加命名区域和稳定的区域邻接语义，区分内部处理、允许离开和阻止离开 |
| 区域键位 | ETAF `:keys` 支持作用域及就近处理；当前禁止以可打印字符开始的多键序列 | 完成 `r` 选择入口、最小保留键、可选方向映射及无歧义的冲突校验 |
| 帮助 | `?` 当前打开执行型 `etaf-palette`，且可被应用绑定覆盖 | 提供导航态默认按键帮助，区分查看与执行，显示有效绑定来源 |
| 原地输入 | `etaf-text-input` 已声明单行和多行原地编辑、原生输入、补全及受控值；结束方式包含保留文本的 `blur` | 完成 Escape 留稿退出、再次编辑恢复完整现场、原生边界跨区及 GUI 验收 |
| Escape 与中断 | 输入组件当前将 Escape 和 `C-g` 用于取消并恢复激活值；浮层契约也使用 `C-g` 关闭 | Escape 按层级退出且不默认回滚输入；删除框架及组件的应用级 `C-g` 绑定，保留原生中断 |
| 应用入口 | 已有程序聚焦、局部绑定和可复用列表控件 | 提供简单的区域命令及可选序号能力，由应用显式绑定；不自动创建裸字母入口 |

上述基础接口不构成本方案完成的证据。交付时先完成提供方原语与 ETAF 公共入口，再迁移目录控件及维护中的消费应用、示例、手册和公共测试；去除被替代的绑定与取消路径，按工作区要求记录可复现的集成版本。

## 11 可观察验收

正确性测试通过公开输入、输出和生命周期观察结果，GUI 流程使用真实键盘事件。以下是目标场景，不能作为已通过的测试清单。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 默认键位边界 | 导航态的 `r`、`?` 和方向键按框架协议工作；应用业务声明不能隐式覆盖；其他字母默认可用 |
| 编辑文字 | 输入 `r`、`?`、`h/j/k/l`、数字及中文时得到文字，不误触导航或业务命令 |
| 两套方向映射 | 两套方案在相同界面和状态下得到相同方向结果；启用冲突方案时原有效绑定保留 |
| 列表与空间导航 | 列表内部上下移动；没有左右内部操作时可直接跨区；真实边界按规则离开；一次事件只完成一步 |
| 嵌套区域 | 方向按区域邻接与父层出口选择，提示显示正确父路径；回到区域后恢复有效内部位置 |
| 固定提示与直达键 | `r` 下的字母稳定；声明提示不自动创建裸键；应用自定义直达键与业务键按作用域工作 |
| 序号操作 | 应用启用后可用 `r l 3`，或显式配置的 `l3` 激活第 3 项；越界、禁用和顺序变化不误激活 |
| Escape 留稿 | 编辑后 Escape 进入导航态，文字、控件焦点和编辑现场保留；再次激活可继续编辑及撤销 |
| 输入临时状态 | 候选或补全先处理 Escape 和方向；不发生同一次退出多个层级或把候选字母当导航命令 |
| 真实文本边界 | 单行两端可以按契约出区；多行中间行首、自动换行和视口边缘不被误判成文本尽头 |
| 原生中断 | `C-g` 保持 Emacs 中断；临时资源正确清理，不触发应用关闭、提交或输入回滚 |
| 模态与目标失效 | 导航不进入模态背景；目标隐藏、删除和配置更新失败后仍有有效焦点及绑定 |
| 帮助 | 显示当前实际生效的绑定和来源；用户改键后同步更新；查看动作不执行业务 |
| 生命周期与实例隔离 | 两个应用实例的区域、键位、草稿和位置记忆互不污染；卸载后无旧绑定和回调 |
| 连续输入与显示 | 长按、快速组合、窗口缩放和后台更新后目标正确、焦点可见、行高稳定；GUI 与终端分别验证 |
| 性能 | 使用维护中的场景与工具比较输入到显示提交的延迟；三组最终样本及正确性结果满足对应验收契约 |

完整用户流程至少覆盖：侧栏选择项目，向右进入主体，浏览主体列表，显式向下进入输入区，输入后 Escape 留稿退出，选择另一嵌套区域查看，再返回输入区恢复编辑。过程中同时验证帮助、应用直达键、焦点恢复和原生中断。
