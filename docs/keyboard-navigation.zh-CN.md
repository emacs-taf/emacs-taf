# ETAF 区域导航与键盘交互方案

本方案规定复杂文本应用的区域导航、控件操作、编辑状态和快捷键边界，是 ETAF 生态已确定的目标契约。框架提供最小且一致的导航能力，应用决定业务快捷键和区域直达键。用户可以沿方向自然移动，也可以显式选择区域；离开编辑状态必须保留已经输入的内容。

框架只使用状态键和非打印入口：`Escape` 逐层退出，默认以 `M-g` 进入区域选择，`?` 打开只读帮助；裸字母和数字归应用。最终使用者可以通过框架级配置修改框架入口和方向方案，普通应用业务绑定不能隐式覆盖这些入口。

目标行为与当前实现的差距及现存绑定迁移见[实现状态与交付边界](#10-实现状态与交付边界)。本方案不表示相关功能已经完成；已支持的接口以各包根入口的 Commentary 为准。生态依赖与统一输入路径见[生态架构契约](architecture.zh-CN.md)。

## 1 核心决定

| 主题 | 确定的规则 |
| --- | --- |
| 导航方式 | 方向键优先完成控件内部操作；没有内部用途或到达允许离开的真实边界时，按区域策略进入相邻区域；连续内容消费方向做滚动或翻页 |
| 显式跨区 | 导航态以默认非打印前缀 `M-g` 进入区域选择；前缀加提示字母精确定位，前缀加方向键直接跨区；入口可由框架配置或应用显式更换 |
| 框架保留集 | `Escape`、物理方向键、导航态 `?` 和 `Tab` 是声明期校验的不变量；`C-g` 永不绑定，保持 Emacs 原生中断 |
| 应用键空间 | 裸字母与数字归应用；提示字母保持稳定，不自动成为裸键快捷方式；应用自行决定 `l`、`s` 等直达键 |
| 可选方向方案 | 内置方向键和 Vim 方向映射；方向键是同一组方向命令的分发键，应用与组件不绑定方向键；Vim 映射只有显式启用后才占用 `h/j/k/l` |
| 编辑退出 | `Escape` 退出编辑态并保留草稿和控件焦点；`C-c C-k` 是默认的放弃修改入口；重新编辑时恢复编辑位置与撤销历史 |
| 原生中断 | `C-g` 保留 Emacs 原生中断语义；框架和应用不把它重新绑定成关闭、取消修改或清空输入 |
| 按键帮助 | 导航态 `?` 查看当前有效绑定；帮助从实际声明和配置生成且只读；执行型命令面板经 `M-x` 调用，不占默认键 |
| 基础可达性 | `Tab` 保留为顺序遍历入口，顺序与区域树一致；区域跳转和空间导航提供快速路径 |

上述默认保护限定在相应交互状态和当前应用范围内，不安装影响其他 Emacs buffer 的全局接管。框架级配置可以修改选择入口、帮助、`Tab`、方向方案和边界策略；它不能静默改写应用业务键，应用要支持改键时由应用提供配置。

## 2 区域与焦点模型

### 2.1 按任务建立区域树

区域是用户能够命名并希望直接进入的功能范围，例如侧栏、结果列表、详情、属性表单和输入区。区域可以嵌套，但普通布局包装节点不自动成为导航区域。

| 区域路径 | 内容 |
| --- | --- |
| 应用／侧栏 | 分类或会话列表 |
| 应用／主体／筛选 | 查询和筛选控件 |
| 应用／主体／结果 | 数据列表或表格 |
| 应用／详情／属性 | 负责人、优先级、截止日期等字段 |
| 应用／详情／历史 | 历史记录 |
| 应用／输入区 | 单行或多行编辑组件 |

大量重复记录作为列表项目定位，不为每条记录建立区域。区域树表达任务结构，焦点组表达列表、工具栏、表格等复合控件的内部操作方式；一个区域可以包含多个焦点组。

区域声明包含稳定身份、名称、父区域和默认入口，并可配置提示字母及方向邻接关系。身份限定在所属应用实例内，不能因显示名称、列表排序或布局坐标变化而改变。字段的具体 API 名称由实现时的公共入口契约确定。

### 2.2 焦点与编辑状态

逻辑焦点、业务选择、文本光标与选区分别表达不同状态。移动焦点不自动清空多选，也不自动提交业务数据。每个输入上下文只有一个真实焦点权威；区域位置记忆和跳转历史是恢复信息，不能成为另一套焦点状态。

进入区域时，依次选择上次仍有效的操作位置、声明的默认入口、适合当前状态的可操作控件。没有交互控件但需要阅读的区域可以提供程序可聚焦的内容入口，不必为每个区域容器增加 Tab 停靠点。

焦点样式必须清楚且不改变布局尺寸；区域提示和帮助也不能通过增加字号、图标高度或边框宽度改变标准行高。进入目标时执行最小必要滚动，使目标可见，同时保持未受影响区域的位置。

### 2.3 位置恢复

区域记录稳定目标身份。重排后跟随原对象；目标删除、隐藏或禁用时，按后继、前驱、有效区域入口的顺序选择适用的回退。关闭浮层后恢复有效调用入口；应用主动切换内容后，旧入口失效时采用新内容的默认入口。

主动跨区域跳转可以记录返回位置，普通方向键逐项移动不逐次填充跳转历史。返回能力通过公共命令提供，是否绑定快捷键由应用或用户决定。

### 2.4 顺序遍历

`Tab` 和 `Shift-Tab` 在导航态按顺序移动焦点：区域按区域树深度优先与已提交的阅读顺序排列，每个区域内按已提交的 tab 停靠点排列，两个方向的顺序互为逆序。进入区域时使用与显式跳转相同的有效入口规则（上次仍有效的操作位置、声明的默认入口、适合当前状态的可操作控件）。禁用、隐藏和被模态范围排除的停靠点不参与，遍历在应用或最内层模态界面内循环。没有交互控件但需要阅读的区域通过声明的内容入口参与一个停靠点，布局容器不增加停靠点。

编辑态的 `Tab` 遵循控件公开契约：一般字段移动到下一个控件，多行控件可以声明插入制表符；顺序仍与导航态一致。应用不绑定 `Tab`，冲突在声明期校验。

## 3 交互状态与默认键位

### 3.1 状态与按键含义

| 状态 | 文字键 | 方向键 | Escape |
| --- | --- | --- | --- |
| 导航态 | 执行当前有效的应用命令；`M-g` 选择区域，`?` 查看帮助 | 按控件内部操作与边界规则导航 | 处理当前可关闭的临时界面；没有临时界面时不丢弃数据 |
| 编辑态 | 正常输入，包括 `r`、`?`、区域字母和数字 | 原生编辑优先，真实边界按组件契约交给区域导航 | 退出编辑态，保留文字和控件焦点；一次只退出这一层 |
| 区域选择态 | 解释当前范围内声明的区域提示字母 | 直接选择对应方向的区域 | 取消选择，恢复进入选择前的状态 |
| 帮助或其他临时界面 | 按该界面的输入规则处理 | 操作当前界面 | 先关闭最内层临时界面，恢复有效入口 |

输入法候选、补全等原生临时交互先处理 Escape。一次按键不能同时关闭候选、退出编辑并关闭外层对话框。状态转换复用 Emacs 命令循环和提供方生命周期，不在应用中另建事件循环。区域选择是前缀状态，`C-g` 由 Emacs 原生取消前缀，不产生需要清理的框架状态。

### 3.2 两套方向映射

| 方向语义 | 默认方向键方案 | 可选 Vim 方向方案 |
| --- | --- | --- |
| 左 | `←` | `h` |
| 下 | `↓` | `j` |
| 上 | `↑` | `k` |
| 右 | `→` | `l` |

两套映射调用同一组方向命令。方向键是分发键，不是业务绑定：控件通过方向协议声明内部操作，应用和组件不把方向键作为自己的按键绑定。两套方案使用相同的区域、边界和恢复规则；Vim 方案可以同时保留物理方向键，它只表示方向映射，不承诺完整 Vim 或 Evil 键位兼容。

默认方案不预留 `h/j/k/l`，应用可以正常使用它们。启用 Vim 映射是一次原子操作：框架与应用声明、区域提示字母和组件键逐一比对，存在冲突时列出按键、作用域和来源并整体拒绝，保留此前有效配置；用户可以先更改一方再启用。不能根据最近注册顺序或短超时猜测用户意图。

键位映射与边界策略独立。用户可选择方向键或 Vim 映射，也可配置某类控件保留原生边界行为；修改键位不应改变控件的业务语义。

### 3.3 Emacs 原生中断

`C-g` 继续由 Emacs 处理。框架和应用不得为区域选择、文本编辑、对话框、帮助或其他组件重新绑定它，也不得把原生 quit 改解释为提交、回滚或关闭业务对象；组件不得用 `C-g` 承担取消动作。显式的应用关闭和取消操作使用其公开命令及 Escape 层级。

命令被原生中断时，框架释放临时提示、跟踪和局部资源，保持已接受的输入及有效焦点状态；必要清理不吞掉或替换原生中断语义。

## 4 方向导航与区域选择

### 4.1 内部操作与真实边界

方向按键的分发顺序固定：原生临时交互（输入法、补全）→ 编辑态的原生移动 → 焦点控件的方向处理 → 区域邻接与父层出口。每个输入事件只产生一个确定结果。

| 结果 | 含义 | 后续处理 |
| --- | --- | --- |
| 已处理 | 完成内部移动、滚动、翻页、展开、选择或其他方向操作 | 结束本次请求 |
| 允许离开 | 该方向没有内部用途，或到达允许离开的真实边界 | 查询相邻区域 |
| 当前不能离开 | 原生临时交互正在接管，或控件明确保留该方向 | 留在当前交互中 |

不能用 point 是否变化、某个移动命令是否报错来代替上述判断。展开树节点、改变选区或切换候选都可能没有移动 point，却已完成内部操作。移动失败或未知状态也不能自动视为允许离开。

普通离散控件（列表、树、表单、按钮组）采用内部操作优先、边界允许出区的默认策略；没有相邻有效区域时停留。连续内容（长文档、日志、历史记录、媒体时间轴）默认消费方向做滚动、翻页或定位，不在边缘自动出区；离开连续内容使用区域选择入口、`Tab` 或应用直达键。用户可以把边界策略改成保守的保留，但不能以未验证的按键释放检测或很短的超时作为可靠性保证。

| 场景 | 输入 | 目标行为 |
| --- | --- | --- |
| 竖向列表中间 | `↓` | 下一项 |
| 竖向列表最后一项 | `↓` | 若下方有有效相邻区域则进入，否则停留 |
| 竖向列表没有左右内部操作 | `→` | 进入右侧区域 |
| 树节点仍可展开或进入子节点 | `→` | 完成树的内部操作 |
| 单行输入中间 | `←` | 光标左移 |
| 单行输入最开头 | `←` | 进入左侧有效区域 |
| 多行文本中间 | `↑` | 按原生视觉行规则移动 |
| 多行文本最上面的可编辑视觉行 | `↑` | 没有内部移动可做且允许离开时，进入上方区域 |
| 长文档或阅读区 | `↑`、`↓` | 滚动内容，不离开区域 |
| 媒体时间轴或分页阅读 | `←`、`→` | 完成控件声明的内部定位 |

长按产生的后续方向事件可能在到达边界后继续跨区，这是边界放行策略的明确行为。支持配置保守的边界策略；真实 GUI 和终端分别验证连续输入，保守策略和默认策略都进入验收。

### 4.2 相邻区域的选择

跨区域命令以区域为目标，不在整个界面的按钮集合中任意挑选最近控件。优先采用应用声明的方向邻接关系；没有声明时按已提交几何选择，同级没有目标时再向父层寻找出口。例如主体的左侧出口可以明确指向侧栏，侧栏的右侧出口指回主体；主体下方指向输入区。区域内部位置记忆负责让返回操作落到先前的有效控件。

几何选择以当前焦点控件的已提交矩形为锚点，按固定顺序决胜：候选近边越过锚点远边；与锚点垂直投影相交的候选优先，没有相交候选时才放宽到全部候选；候选按轴向间隙、垂直中心距、已提交阅读顺序依次比较。所有判断使用已提交区域边界，不保存另一份应用侧坐标。隐藏、不可进入或被模态范围排除的区域不参与选择；相邻区域不可达时不穿透到背景控件。

### 4.3 区域前缀

导航态下按 `M-g`（框架默认入口，可由框架配置或应用显式更换）进入区域选择，在当前有效范围内显示应用声明的固定区域字母和可用方向。有效范围为当前应用或最内层模态界面；提示展示区域名称和必要的父路径，当前区域清楚可辨。用户需要保留原生 `M-g` 前缀命令时，通过框架级配置更换入口。

- `M-g` 加区域字母：立即进入对应区域，恢复其有效入口，然后结束本次选择。
- `M-g` 加当前方案的方向键：跳过控件内部导航，直接按区域邻接关系跳转。
- Escape：取消区域选择，恢复原来的焦点和状态；`C-g` 由 Emacs 原生取消前缀。
- `?`：说明当前区域选择中的有效键位和目标。
- 其他按键：保留在选择态并提示有效字母，不重新分配目标，也不执行应用命令。

熟练用户可以连续输入，不需要等待提示绘制。区域提示不依赖短时连击，也不能改变布局。选择过程中目标失效时，保留或恢复原来的有效位置并说明原因，不能把同一个字母重新分配给另一个目标后执行。

区域字母可以指向嵌套区域；同一次提示范围内必须唯一。应用只为需要字母入口的区域分配字母，其他子区通过空间导航、顺序遍历或公开跳转入口到达。大量子区按父区域收窄列表并展示路径，不能把布局包装层或每条列表记录都变成字母目标。

启用 Vim 方向映射时，`h/j/k/l` 是方向键，区域提示字母不能使用这四个字母；声明期和方案启用时的校验按 3.2 的规则报告冲突。面向两种方案的应用应避免把 `h/j/k/l` 用作提示字母。

### 4.4 提示字母与应用直达键

为侧栏声明提示字母 `l`，只建立 `M-g l` 这一入口，不自动创建裸 `l` 的绑定。应用可以另行把裸 `l` 绑定到侧栏，也可以把它保留给业务操作。

若启用 Vim 方向映射，`M-g l` 已表示向右区域；此时提示字母 `l` 不能再指向另一个目标。冲突由配置校验报告，应用或用户显式调整一方。框架不为了预防可选方案的冲突，在默认方案下额外封锁所有字母。

## 5 编辑退出与输入保护

### 5.1 Escape 保留输入

普通编辑状态下，`Escape` 结束编辑态并进入导航态，逻辑焦点仍锚定在输入控件上。已经输入的文字、光标位置、选区、滚动位置和撤销历史应保留。此时方向键交给导航系统；`M-g` 和应用快捷键可以正常使用。通过 `RET` 等控件公开激活方式重新编辑时，从保留的位置继续。

```text
输入到一半
  → Escape，保留草稿并退出编辑态
  → M-g 加区域字母，进入其他区域查看
  → 返回输入控件并激活
  → 从原位置继续编辑
```

Escape 的层级固定，一次按键只退出一层：输入法或补全候选 → 编辑状态 → 最内层可关闭的临时界面（下拉、浮层、对话框、帮助或区域选择）→ 没有可退层时不执行清空。包含输入框的对话框因此需要先退出编辑、再关闭对话框；关闭时草稿是保留还是丢弃由该对话框的公开关闭契约决定。

离开编辑、保留草稿、提交和放弃修改是不同操作。`C-c C-k` 是默认的放弃修改入口，按业务契约恢复激活时的基准值；Escape 不恢复旧值。切换区域不自动发送或保存到外部系统。

框架提供可在编辑态调用的区域导航命令，应用或用户可以配置非字符入口以减少步骤，但不增加强制的默认组合键。主流程不依赖这个可选入口。

### 5.2 边界判定与原生输入

单行输入的两端是可判定的左右边界。多行输入中间一行的行首按左，仍可能移动到上一行末尾；自动换行和滚动视口的边缘也不等于文本边界。编辑组件结合原生移动、视觉行和真实文本范围给出方向处理结果，不能由应用按字符列号猜测。

输入法组合、候选选择、补全及文本选区优先遵循原生编辑规则。Escape 先交给正在进行的临时交互，不能同一次又触发退出编辑。候选字母和未确认文本不能被区域选择器当成命令。

退出再进入的行为要通过完整编辑会话验证，不能只证明文本字符串相同。后台内容更新、区域跳转和重新显示不得清空撤销历史、把光标一律放到末尾，或结束其他输入实例的会话。

GUI Escape 与终端 ESC、Meta 和功能键序列分别验证，沿用 Emacs 输入解码，不把原始 ESC 字节定义为破坏其他序列识别的全局命令。

## 6 应用绑定与冲突规则

### 6.1 简单声明

应用继续通过“按键、处理函数、说明”声明绑定。普通命令和匿名回调均可作为处理器；声明位置决定作用域，挂载和卸载决定生命周期。根级业务键作用于应用，区域级业务键作用于该区域及允许的后代。

现有 `:keys` 的 `(KEY COMMAND [LABEL])` 形式是绑定入口的基础。区域跳转、按序号选择等能力通过公共命令或命令构造入口提供，让应用不用自行处理坐标、焦点、编辑会话和恢复。新增函数签名在实现后由包根入口统一维护，不在本方案预先定义另一份 API 清单。

| 声明范围 | 应用选择的键 | 动作示例 |
| --- | --- | --- |
| 应用 | `g` | 刷新当前数据 |
| 应用 | `l` | 进入侧栏区域 |
| 应用 | `e` | 进入输入区 |
| 侧栏 | `1` 到 `9` | 激活对应编号的项目 |

这些业务键均为应用示例，不是框架默认绑定。框架不要求应用使用单字母，不自动占用数字，也不要求普通绑定先注册另一套业务对象。

### 6.2 冲突处理

| 情况 | 规则 |
| --- | --- |
| 业务绑定或组件键触及框架保留集 | 声明或挂载期报错，指出按键、作用域和来源 |
| 同一作用域重复绑定同一个键 | 报告冲突，不采用最后注册者获胜 |
| 子区域与父区域使用同一个普通业务键 | 就近区域生效；帮助显示实际来源 |
| 互不重叠的区域使用同一个业务键 | 允许 |
| 同一个键同时作为完整命令和多键前缀 | 报告结构冲突，要求改为无歧义的声明 |
| 启用的方向方案与应用绑定或提示字母冲突 | 原子拒绝方案启用，列出全部冲突，保留此前有效配置 |
| 显式修改框架键位配置 | 统一更新导航入口、校验和帮助；不能通过普通业务绑定暗中覆盖 |

保留集是不变量，不参与运行期优先级：`Escape`、物理方向键、导航态 `?`、`Tab` 在任何作用域都不能被应用或组件覆写；`C-g` 不建立任何绑定。方向方案字母（`h/j/k/l`）只在对应方案启用时进入保留集。

校验在三个时机发生：应用声明和挂载时报告结构冲突；方案启用或用户修改框架键位时一次性校验并原子生效；运行期按“交互状态 → 就近作用域 → 框架默认”确定唯一处理器，不使用超时或注册顺序。用户级配置只能修改框架入口（选择前缀、帮助、`Tab`、方向方案和边界策略），不能静默改写应用业务键。

编辑态的正常文字输入不属于保留键冲突。模态范围外的业务绑定不参与当前解析。一次输入只执行一个确定的处理器，禁用子控件不能把同一输入意外交给父业务动作。

静态检查覆盖框架管理的声明；运行时按键解释还需反映 Emacs major mode、minor mode、用户映射和当前交互状态。不能宣称静态校验已经排除所有用户配置冲突。

### 6.3 项目序号

单数字 `1` 到 `9` 由应用绑定并立即执行：`l3` 可以是应用绑定的 `l` 进入侧栏、随后侧栏的 `3` 激活第 3 项；没有裸 `l` 时用 `M-g l 3`。区域跳转只移动焦点，序号操作才按列表声明执行选择或打开。

编号从 1 开始，对应明确的显示顺序。滚动不重新编号；筛选、排序及分页采用组件声明并显示的编号范围。禁用项不能造成无提示的编号位移，越界序号不得改为激活其他项目。

需要任意位数入口时，应用绑定一个读取命令，通过 minibuffer 使用原生 `read-number` 语义读取数字，例如应用的 `#` 命令；数字和 `RET` 由 minibuffer 处理，`C-g` 原生取消。不使用多键 `:keys` 序列或短超时区分 `3` 和 `30`。框架提供把序号解析为稳定项目身份的入口，异步更新或分页后重新确认可见编号，不能按新的第 N 项执行旧请求。虚拟化或尚未加载的项目通过提供方支持的数据与显示接口定位。

## 7 按键帮助与可发现性

导航态下 `?` 展示当前有效的框架、应用和区域绑定，说明当前区域、交互状态、动作名称及绑定来源。帮助内容是只读的，从同一份有效绑定数据生成：应用声明、区域提示和用户重新绑定后同步更新；被遮蔽的父绑定不伪装成当前可执行入口。帮助支持搜索，行内显示“按哪个键执行”，查看条目不能触发业务动作。

应用通过 `:help` 一类的声明贡献说明、链接和操作建议等非绑定内容，不再用自己的 keymap 覆盖 `?`。执行型命令面板 `etaf-palette` 作为独立能力保留，默认只经 `M-x` 调用，应用可以自行绑定；它不占默认键。若帮助提供执行入口，操作必须显式，并进入面板的独立命令。

编辑态的 `?` 是普通字符。帮助及导航功能提供可从 `M-x` 调用的公共命令，应用或用户可自行添加非字符快捷方式，不因此扩大默认保留键集合。图标控件和区域提供可读名称，实际读屏适配与键盘可见焦点分别验证。

## 8 作用域与生命周期

区域跳转、帮助和快捷键使用同一份已提交的目标与可见性事实。失败的显示更新不能让旧画面使用新目标；目标失效时报告并回退，后台更新不抢夺当前焦点。

模态界面形成区域导航边界。方向、区域字母、数字选择和应用直达命令均不能绕过这个边界进入背景。只读内容与禁用操作分别处理：需要阅读或复制的内容可以提供入口，禁用动作不能执行。

绑定及提示随所属区域挂载、更新和释放，卸载或窗口失效后不保留旧回调。区域选择被原生中断时只清理临时资源，保留已接受数据并让 Emacs 中断正常传播。

高频方向输入复用已提交的身份与区域索引，不默认每次重新扫描、排序所有控件。性能记录覆盖命令处理、必要更新及实际显示提交；具体测量方法与证据边界沿用[工作区工具手册](manual.md)和[生态性能契约](architecture.zh-CN.md#113-性能门槛与证据边界)。

## 9 分层职责

| 层次 | 拥有的职责 |
| --- | --- |
| Ebox | 已提交节点身份、几何与可见性、真实焦点、滚动、原生输入边界，以及方向三态和编辑会话原语 |
| ETAF | 区域和导航命令的公共入口、保留集与声明期校验、选择入口、方向方案、作用域绑定、事件上下文与生命周期；使用 Ebox 的事实，不维护第二份目标或焦点权威 |
| ETAF UI | 控件内部方向语义、编辑与导航状态转换、区域提示和按键帮助等可复用界面；组件不绑定保留键或方案字母 |
| 应用 | 语义区域划分、固定提示字母、业务命令（含裸字母和数字）、可选直达键和数字速选、业务选择、草稿及提交策略 |
| 最终使用者 | 选择方向方案，修改框架入口和边界策略，按需要配置可选快捷入口；不能静默改写应用业务键 |

应用及目录组件只使用 ETAF 和 ETAF UI 公共接口。缺少的共享能力在提供方补齐，不能由每个应用复制焦点扫描、按键分发或编辑会话管理。`Tab`、控件激活及 Emacs 原生行为继续沿各自契约工作，不把更多按键无条件加入应用级禁止绑定名单。

## 10 实现状态与交付边界

当前公开契约已有可复用基础，但与本方案仍有以下差距。具体可调用签名以 [ETAF 入口](https://forgejo.vhkd.top/emacs-taf/etaf/src/branch/main/etaf.el)、[ETAF UI 入口](https://forgejo.vhkd.top/emacs-taf/etaf-ui/src/branch/main/etaf-ui.el)和 [Ebox 入口](https://forgejo.vhkd.top/emacs-taf/ebox/src/branch/main/ebox.el)为准。

| 能力 | 当前公开契约 | 目标差距 |
| --- | --- | --- |
| 焦点与方向 | Ebox 的 `ebox-focus-direction` 支持可选 ROOT 限域；ETAF 以 `etaf-direction` 实现三态（`:on-direction` 返回 `handled`／`hold`／`release`）、separator／slider 步进、区域内移动与边界跨区；无区域时保持 Ebox 空间移动与边缘滚动 | 无（GUI 与终端验收见 §11） |
| 区域键位 | `M-g` 选择入口；`Escape`、`M-g`、`C-g`、方向键、`?`、`Tab` 为声明期保留项，组件调用方 `:keymap` 同样按保留集校验；`etaf-set-direction-scheme` 在原子冲突校验后于 arrows 与 vim 方案间切换 | 无 |
| 帮助 | `?` 是保留键，打开只读 `etaf-help`；`etaf-palette` 经 `M-x` 调用 | 应用独立帮助页可继续迁为 `:help` 声明（可选增强） |
| 原地输入 | Escape 留稿、`C-c C-k` 放弃、方向键在文本边界退编辑并进入相邻区域、再次编辑复用会话恢复光标与撤销已实现 | 无（GUI 验收见 §11） |
| Escape 与中断 | 框架、浮层与输入组件已无 `C-g` 绑定；Escape 按层级退出 | 无（GUI 与终端验收见 §11） |
| 应用入口 | 程序聚焦、`etaf-region-focus` 直达入口与命名区域齐备；单数字由应用绑定，任意位数由应用经 minibuffer 读取 | 无 |

上述基础接口不构成本方案完成的证据。交付时先完成提供方原语与 ETAF 公共入口，再迁移目录控件及维护中的消费应用、示例、手册和公共测试；去除被替代的绑定与取消路径，按工作区要求记录可复现的集成版本。

## 11 可观察验收

正确性测试通过公开输入、输出和生命周期观察结果，GUI 流程使用真实键盘事件。以下是目标场景，不能作为已通过的测试清单。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 默认键位边界 | 导航态的 `M-g`、`?` 和方向键按框架协议工作；`Escape`、`Tab`、方案字母的声明期冲突被拒绝；`C-g` 保持原生；`r`、`l` 等字母仍可作业务键 |
| 编辑文字 | 输入 `r`、`?`、`h/j/k/l`、数字及中文时得到文字，不误触导航或业务命令 |

| 方向协议 | `:on-direction` 的 `handled`／`hold` 停止、`release` 放行；separator／slider 按方向步进；区域内没有该方向目标时进入相邻区域的入口，无相邻区域则停留 |
| 列表与空间导航 | 列表内部移动由 `:on-direction` 或焦点组完成；区域内没有该方向目标时进入相邻区域；离散控件按边界放行策略离开；一次事件只完成一步 |
| 连续内容滚动 | 阅读区、日志和媒体时间轴的方向键执行滚动、翻页或定位且不离开区域；退出使用 `M-g`、`Tab` 或应用直达键 |
| 顺序遍历 | `Tab` 与 `Shift-Tab` 按区域树和停靠点顺序互为逆序，跳过禁用和隐藏项，在模态范围内循环 |
| 嵌套区域 | 方向按区域邻接与父层出口选择，提示显示正确父路径；回到区域后恢复有效内部位置 |
| 固定提示与直达键 | `M-g` 下的字母稳定；声明提示不自动创建裸键；应用自定义直达键与业务键按作用域工作 |
| 序号操作 | 应用启用后可用 `M-g l 3` 或应用读取命令的完整序号；越界、禁用和顺序变化不误激活 |
| Escape 留稿 | 编辑后 Escape 进入导航态，文字、控件焦点和编辑现场保留；再次激活可继续编辑及撤销；`C-c C-k` 恢复基准值 |
| 对话框层级 | 含输入框的对话框第一次 Escape 退出编辑并保留草稿，第二次关闭对话框；一次按键不跨层 |
| 输入临时状态 | 候选或补全先处理 Escape 和方向；不发生同一次退出多个层级或把候选字母当导航命令 |
| 真实文本边界 | 单行两端与多行首尾退编辑并进入相邻区域；多行中间行首、自动换行和视口边缘不被误判成文本尽头；再次激活字段恢复光标位置与撤销历史 |
| 原生中断 | `C-g` 保持 Emacs 中断；临时资源正确清理，不触发应用关闭、提交或输入回滚 |
| 模态与目标失效 | 导航不进入模态背景；目标隐藏、删除和配置更新失败后仍有有效焦点及绑定 |
| 帮助 | `?` 显示实际生效的绑定和来源；用户改键后同步更新；查看不执行业务；palette 经 `M-x` 可到达且不占 `?` |
| 声明期校验 | 与保留集（含方向键、`Tab`、`?`）或方案冲突的应用声明在挂载时报错并指出按键、作用域和来源，不静默生效 |
| 生命周期与实例隔离 | 两个应用实例的区域、键位、草稿和位置记忆互不污染；卸载后无旧绑定和回调 |
| 连续输入与显示 | 长按、快速组合、窗口缩放和后台更新后目标正确、焦点可见、行高稳定；GUI 与终端分别验证 |
| 性能 | 使用维护中的场景与工具比较输入到显示提交的延迟；三组最终样本及正确性结果满足对应验收契约 |

完整用户流程至少覆盖：侧栏选择项目，向右进入主体，浏览主体列表，显式向下进入输入区，输入后 Escape 留稿退出，选择另一嵌套区域查看，再返回输入区恢复编辑。过程中同时验证帮助、应用直达键、焦点恢复和原生中断。
